# CRUD resource screens

<!-- Generated by php artisan standards:install from tey/standards; do not edit. -->

`standards:make crud <Record>` emits a whole workspace-owned resource: model and migration (with lock_version), a policy gated by the record's capability then its permissions, a provider that registers both with the kit, CRUDDY controllers and routes, form requests, one Action per write (principal first, stale writes refused), typed ViewModels, Index, Form and Show pages, server toasts on save, and feature tests on the app's synthetic fixture. `--bulk` adds selection and a bulk delete, `--mcp` Read, Write (create or update) and Delete capability tools over a List action, `--soft-deletes` soft deletes and a restoration. With `--module=<Module>` the record nests under the module's prefix, `/<module>/<records>` named `<module>.<records>.*` (the main record at `/<module>`), as one of the module's pages (see ui-page.module-urls).

Scaffold: `php artisan standards:make crud --flavor=resource <Name>`.

Kit: @kit/ui DataTable, @kit/ui FormCard, @kit/ui ButtonGroup, @kit/ui InertiaAction, @kit/ui DropdownAction.
Checks: 20, 21, actions, descriptors, toast, js-imports. Run `php artisan standards:check --changed` before committing.

Not sure this is the right leaf? It answers "Is it a full set of CRUD screens, a workflow page beyond CRUD, a full-screen display, or a full-screen sub-page?" Call bakery.find, or run `php artisan standards:pattern --recipe=ui-page.crud-resource` to see its siblings.

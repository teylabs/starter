# Choosing a select

<!-- Generated by php artisan standards:install from tey/standards; do not edit. -->

A judgement call, not a check (Jasper, 2026-11-18): InputSelect is the standard go-to; a plain Select is right only for a short fixed list the code owns, that always holds a value, needs no search and has no "none" choice (a status on a dense settings row, a unit beside a number, a role from three). Ask at build time: does the list come from data, or can it grow? Will anyone need to search it? Is the field optional, or must people be able to clear it? Does "no choice" need its own label ("Any scope", "No team")? Any yes means InputSelect (search past 8 options or `filter="remote"`, `clearable`, the empty label as its placeholder). A choice that changes what a page shows (a sort order, a view) is InlineDropdown, not a bordered field. See tey/kit docs/form-fields.md, "Choosing a select".

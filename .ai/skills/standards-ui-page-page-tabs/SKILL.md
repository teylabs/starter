# Breadcrumbs and page tabs

<!-- Generated by php artisan standards:install from tey/standards; do not edit. -->

Breadcrumbs are the kit's bar under the header, always. A module's sibling pages are PageTabs, registered with Registry::modulePage and sent by the server as the page's layout.navigation, which <Page> draws. A record's sections are PageTabs too, from the record ViewModel's own navigation, inside the record's frame under its header. No hand-rolled sub-nav strips. Nested navigation, one level at a time, each sent by the server (Jasper, Nov 22; tey/kit 0.46.0): (1) level 2 is page tabs, one underline row; (2) a nested module's row (a tab's own 2 to 5 sub-pages) is pills, PageTabs variant="secondary" under the tabs: never a third row, never above the tabs and never a filter (filters are SegmentLinks); (3) a module whose pages carry a group (Registry::modulePage(..., group: 'Invoicing')) is a sidebar module: <Page> frames it with SettingsFrame's sidebar, one labelled group per group, and draws no tab row. Group a module at about 8 pages or more, or when its pages fall into groups; nothing switches automatically, and a nested module is never a sidebar; (4) about 15 pages or more, or parts that don't relate, get a hub landing page; (5) a page that leaves its section's layout breaks out (ui-page.back-strip). On phones each level is a select (the sidebar's groups become option groups).

Kit: shell Layout (pages/Workspace/Layout.vue), @kit/ui Page, @kit/ui PageTabs, tey/kit Registry::modulePage().
- `PageTabs` from `@kit/ui` for the page tabs: A module's sibling pages, or a record's sections: route links with the current one marked (props: tabs, label).
- `Page` from `@kit/ui` for the page: Draws the page's layout.navigation as PageTabs above its heading (props: default slot).
Checks: none. Run `php artisan standards:check --changed` before committing.

Conventions:
- Breadcrumbs = bar, always (Jasper, fleet-wide): the shell's Layout draws the whole trail under the header, the current page last, so every page with route breadcrumbs shows one trail in the same place (a page with no trail gets no bar). Don't pass breadcrumbs="page" and don't draw a trail inside a page. The trail comes from the route's breadcrumbs through the page ViewModel's layout().
- A module's sibling pages = PageTabs. Register each with Registry::modulePage($module, $ability, $label, $suffix, order:, active:) in the module's service provider, its suffix nested under the module's prefix (`bookings/calendar`, as ui-page.module-urls says; the kit warns in development otherwise). The server sends the ones the viewer may open as the page's layout.navigation, and a top-level <Page> draws them. Don't hand-write the tab list in a page.
- A record's sections = PageTabs, as AppraisalBench's case pages do: the record ViewModel sets its own layout.navigation, and the record's frame (its folder Layout.vue) renders one <PageTabs> from it under the record's header. That replaces the module's tabs, so a page never has two tab rows.
- No hand-rolled sub-nav strips: no row of links under the header or above the heading built from a page's own array, and no new use of the kit's deprecated SubNav strip (Layout sub-nav="strip").

# Domain model

<!-- Generated by php artisan standards:install from tey/standards; do not edit. -->

`standards:make model <Name>` emits the model, its migration, a factory and tests that run on the app's own database. Answer two questions with flags. Does it need composite-FK tenancy and a lock_version stale-write guard? `--tenant` makes it workspace-owned through tey/kit's BelongsToWorkspace (every query scoped to the current workspace, workspace_required outside one, workspace_mismatch for another workspace's row) and GuardsStaleWrites (updateIfCurrent refuses a stale lock_version), with a constrained workspace_id that restricts deletes, a unique (workspace_id, id) as the target of child tables' composite foreign keys, and a capability-gated policy. Enum or check-constraint fields? `--enum=<field>:<Enum>` adds a backed enum and an enum column that the database itself constrains (a check constraint on SQLite and PostgreSQL). `--soft-deletes`, `--media` (spatie/laravel-medialibrary) and `--sortable` (a position column) add to it. The tests prove factory validity, the database's refusal of a value outside each enum, and with `--tenant` cross-workspace isolation, the workspace foreign key and the stale-write refusal. `standards:make crud` builds its model through this generator.

Scaffold: `php artisan standards:make model --flavor=domain <Name>`.
